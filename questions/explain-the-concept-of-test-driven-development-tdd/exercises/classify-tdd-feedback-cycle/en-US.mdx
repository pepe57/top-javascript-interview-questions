Which statements accurately describe test-driven development? Select all that apply.

## Options

### red-next-behavior (correct)

Start with a focused failing test that describes the next behavior to implement.

> The red step establishes an observable requirement and confirms the test can fail.

### green-minimum-change (correct)

Make the smallest implementation change that gets the new test and existing suite passing.

> The green step restores feedback quickly before broader design cleanup.

### refactor-while-green (correct)

Improve structure while repeatedly keeping the tests green.

> Passing tests provide a regression harness during the refactor step.

### guarantees-requirements

Following red-green-refactor guarantees that the team specified the correct product behavior.

> Tests can faithfully encode an incorrect or incomplete requirement.

### replaces-other-testing

TDD eliminates the need for exploratory, integration, accessibility, performance, and operational testing.

> Those risks require complementary techniques beyond a unit-level feedback cycle.
